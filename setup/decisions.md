# Locked decisions

These decisions define the harness contract. Change them deliberately, not per
project. Every generated repository must be explainable by this file.

## Scope

The harness standardizes what is common to every repository:

- agent guidelines (`AGENTS.md`);
- commit and push policy;
- versioning, release and release notes;
- the CI, build and deploy contracts;
- secret and data hygiene;
- access to the universal skill library.

The harness does **not** cover:

- technology stacks or frameworks (React, Expo, Expo Router, Gradle, Cargo, ...);
- architecture or layering rules;
- dependency selection or package managers;
- application code.

Architecture may become a separate skill in the future. Until then, the
generated `AGENTS.md` deliberately contains no architecture section.

## Project types

Exactly five, used only to choose which questions to ask and which generic jobs
to generate:

| Type | Meaning |
| --- | --- |
| `web` | Runs in a browser and is deployed to a host. |
| `mobile` | Ships as an application for a mobile platform. |
| `desktop` | Ships as an installer or archive for a desktop platform. |
| `library` | Ships as a reusable package, CLI or archive. |
| `data` | Content or data repository where files are the product. |

No command, dependency or tool is inferred from the type.

## Decisions

| Area | Decision | Rationale |
| --- | --- | --- |
| CI/build depth | Ask per project: `full`, `ci` or `release-only` | Repos have different maturity levels. |
| Release trigger | GitHub Actions `workflow_dispatch` with `bump`, `preid`, `version`, `summary` | One path for every generated project. |
| Version source | Tags only by default; a file plus field only when declared | Works for every project type. |
| Agent guidelines | A single, self-contained `AGENTS.md` | Matches existing repos; no config required. |
| Skills | Git submodule at `.agent/`, sparse checkout limited to `skills/` | One pinned source of truth, no duplication. |
| Skill access | `AGENTS.md` instructs the agent to read `.agent/skills/<id>/SKILL.md` | Works for any agent that can read files. |
| Default skills | `commit-and-push`, `release-summary`, `release-cut`, `add-skill` | Covers the recurring workflows. |
| Commit autonomy | Commit and push when asked | Explicit, never automatic. |
| Setup state | `.harness.json` committed | Reproducible updates and drift audits. |
| Existing `AGENTS.md` | Merge missing sections, never overwrite content | Safe adoption of existing repos. |
| README | Ask per project | Existing READMEs are user-authored. |
| Release notes | Ask the language per project, suggest English with the default sections | User-facing text is a per-project choice. |
| Deploy | Ask per project | Delivery is project-specific. |
| Hygiene files | Pull request template and `CODEOWNERS` only | Useful for every repo, low noise. |
| `.gitignore` defaults | `PLAN.md`/notes, `.env`/secrets, build output and caches | Prevents the common accidents. |
| Harness itself | Self-hosted with its own releases | The harness follows its own contract. |
| New repositories | `main` branch, first tag `v0.1.0` | Modern default, honest pre-1.0 start. |
| `verify-setup` | Harness-only, never copied into projects | Keeps `.agent` limited to skills. |
| Claude Code | Documented global `~/.claude/CLAUDE.md` pointer | No per-project adapter files. |

## Non-negotiable house rules

These apply to every generated project and are never asked:

- Code, identifiers, comments, documentation, commit messages and release notes
  are written in English unless the project explicitly configures another
  release-notes language.
- Commits follow Conventional Commits: `<type>(<scope>): <description>`,
  imperative, lowercase subject, no trailing period, at most 72 characters.
- Allowed types: `feat`, `fix`, `refactor`, `chore`, `docs`, `test`, `perf`,
  `build`, `ci`, `style`.
- No AI attribution anywhere: no `Co-Authored-By`, no "Generated by", no agent,
  tool or session names in commits, tags, releases or code.
- Stage explicit paths. Never `git add -A`, `git add .` or `git commit -a`.
- Never commit secrets, environment files, build output, credentials, keys,
  weights, ROMs or local planning files.
- Never force-push. Never move, delete or reuse an existing release tag.
- Releases only through the configured pipeline, and quality gates must pass
  before a tag is created.
- One release-notes template: `docs/RELEASE_TEMPLATE.md`.
- Never invent data, sources or dependencies. When a field is unknown, use
  `null` and record the gap.
- Run the declared checks before declaring a task done.
- Never commit or push unless the user asked for it.

## Consequences

- `.agent` is read-only. A project agent that wants a new skill writes a
  proposal to `docs/skill-proposals/<id>.md`; the skill is applied in the
  harness repository.
- With a sparse checkout, `.agent` contains only `skills/`. Therefore
  `verify-setup` runs from the harness working tree during setup, update and
  audit; generated CI never runs it.
- Claude Code does not read `AGENTS.md`. A one-time global pointer is
  documented in the harness README; no project file is generated for it.
